# 제안서 종합 소스팩

DILAB 프로젝트 + PyGeek 2026 논문 성과를 바탕으로 **제안서(연구계획서·과제신청서)를 쓰는 연구실 구성원을 위한 단일 출처 자료 모음**입니다. 각자 섹션을 나눠 쓰더라도 이 폴더의 수치·문구·그림을 쓰면 팩트와 문체가 어긋나지 않습니다.

## 폴더 구성

| 파일 | 내용 | 이렇게 쓰세요 |
|---|---|---|
| `01_팩트시트.md` | 프로젝트 요약 · **인용 가능한 수치표** · 타임라인 · 성과 목록 · 용어 사전 | 제안서에 들어가는 **모든 숫자는 여기서만** 가져갑니다 |
| `02_표준_문구_뱅크.md` | 배경·필요성·차별성·기대효과 등 **제안서 문체로 미리 쓴 문단** | 해당 섹션에 복사 후 과제 성격에 맞게 다듬습니다 |
| `03_향후_연구_로드맵.md` | 논문 한계에서 이어지는 **후속 과제 6건** + 단계별 로드맵 | "연구 목표·내용" 섹션의 뼈대로 씁니다 |
| `04_시각자료.pdf` | 핵심 그림 13점 + **제안서용 캡션·해설** | 그림 카탈로그. 실제 파일은 `images/`에서 가져갑니다 |
| `images/` | 카탈로그와 같은 번호의 **고해상도 원본 PNG 13점** | 제안서에 넣을 그림은 여기서. 번호가 `04_시각자료.pdf`의 그림 번호와 1:1 대응 |
| `05_핵심코드_해설.md` | 백엔드 RAG·DB 연동 핵심 코드 발췌 + 해설 (프론트엔드 제외) | 기술적 실현가능성·수행능력 서술의 근거로 씁니다 |
| `참고자료/` | 논문(국·영문) PDF · 발표자료 PDF · 발표 대본 PDF 사본 | 원문 확인용. 대본은 비전공자용 개념 해설서로도 유용합니다 |

## 사용 원칙

1. **수치는 `01_팩트시트.md`의 표만 인용**합니다. 수치마다 원출처(논문·통계 리포트)가 적혀 있으니, 제안서 각주가 필요하면 그 출처를 씁니다.
2. 문구 뱅크의 문단은 **출발점**입니다. 과제 공고의 요구 항목·분량에 맞춰 잘라 쓰되, 수치·주장 부분은 바꾸지 마세요.
3. 그림은 `04_시각자료.pdf`가 아니라 **`images/`의 원본 PNG**(3352px급 고해상도)를 제안서에 넣으세요. PDF는 어떤 그림에 어떤 캡션을 달지 고르는 카탈로그이고, 파일 번호가 서로 1:1 대응합니다.

## ⚠️ 비밀유지 주의

- **협력 기업명·수요기업명은 이 소스팩에 적지 않았습니다.** 제안서에 기업명을 쓸 일이 있으면 반드시 교수님 확인 후에 쓰세요.
- 외부 공개가 이미 이루어진 범위 = **논문(익명화된 서술) · 연구실 홈페이지 DILAB 페이지 · 데모 URL**. 이 범위 밖의 내부 정보(계약·비용·미공개 데이터)는 제안서에 넣기 전에 확인이 필요합니다.
- 이 저장소(`DILAB_cp`)는 비공개 R&D 복제본입니다. 폴더를 팀에 공유할 때는 저장소 접근 권한이 아니라 **폴더 사본**을 전달하세요.
