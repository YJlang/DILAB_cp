DILAB 벡터 인프라 전환
pgvector · Modal → Oracle AI Database 26ai

오픈소스 pgvector(Supabase) + Modal 서버리스 구조를, 저장·임베딩·검색을 하나로 통합하는 Oracle AI Database 26ai 로 전환했습니다. 임베딩과 벡터 검색이 데이터베이스 안(in-DB) 에서 수행됩니다.

배경

왜 Oracle 26ai 인가

수요기업(한국콜마·테팔 등)은 주요 데이터를 저장하는 공간이 보안성이 높고 검증된 솔루션이기를 원합니다. 성능의 문제가 아니라 신뢰와 거버넌스의 문제입니다.

기존 DILAB은 오픈소스 pgvector(PostgreSQL 확장)로 RAG를 구성했습니다. 이를 엔터프라이즈 보안·감사·거버넌스가 검증된 Oracle AI Database 26ai 의 벡터 검색 기능으로 대체해, 같은 서비스를 더 신뢰받는 기반 위에서 제공하는 것이 이번 전환의 목표입니다.

핵심 관점
"데이터를 AI로 보내는 것"이 아니라 "AI를 데이터가 있는 곳으로 가져오는 것". 임베딩·검색을 외부로 빼지 않고 데이터베이스 안에서 처리 → 데이터가 검증된 DB를 떠나지 않습니다.

Oracle AI Database 26ai · 핵심 기능

임베딩과 검색이 DB 안에서 돈다

Oracle 26ai는 별도의 벡터 전용 DB가 아니라, 관계형 데이터베이스에 벡터 기능이 내장된 컨버지드 DB입니다. DILAB이 활용하는 세 가지:

① 컨버지드 — 한 DB, 한 SQL

제품·리뷰·평점 같은 관계형 데이터와 리뷰 임베딩 벡터가 같은 DB에 있어, "벡터 유사도 + 도메인/제품/출처 필터 + 전문가 우선"을 한 번의 SQL로 처리합니다. 데이터를 밖으로 옮길 필요가 없습니다.

② in-DB 임베딩 — 외부 임베더 불필요

다국어 임베딩 모델(ONNX)을 DB에 적재해, 텍스트를 넣으면 DB가 직접 벡터로 변환합니다. 별도의 임베딩 서버(과거 BGE-M3/Cloudflare)가 필요 없습니다.

③ 벡터 검색 — VECTOR_DISTANCE

코사인 거리로 의미가 가까운 근거를 찾고, HNSW 인덱스로 가속합니다. 질문 임베딩부터 근거 검색까지 전 과정이 DB 내부에서 이뤄집니다.

근거기반 신뢰성 강화
평가 점수 산정에 전문가 리뷰 가중치와 표본 수 보정을 도입해, 근거가 얕은 항목이 과신되지 않도록 했습니다. "어디서 나온 결론인지" 추적 가능한 DILAB의 차별점을 Oracle 위에서도 유지·강화합니다.
